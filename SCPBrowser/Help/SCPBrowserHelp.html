SCPBrowser User Guide

An integrated desktop environment for single-cell proteomics: from data import and cell-isolation imaging through quality control, cell-type classification and enrichment analysis, to annotated export.

What SCPBrowser does

SCPBrowser keeps one experiment in one project file. The cell-isolation micrograph, the isolation metadata, the mass-spectrometry run, the quality decisions, the cell-type assignment and the figures all live together and stay linked, so any result can be traced back to the individual cell it came from.

The workflow has a fixed order, because each stage consumes what the previous one produced:

StageWhat it produces
Register a plate (optionally with a cellenONE isolation run)Wells, micrographs, isolation metadata
Import MS quantificationPer-cell protein/peptide quantities
Reconcile cells ↔ runsThe link between a well and its raw file
Quality controlThe set of cells that enter the analysis
Import a reference profileThe classes a cell can be assigned to
ClassifyA cell type per cell, with a score and margin
Reduce dimensions / enrichEmbeddings, clusters, GO terms
ExportAnnotated data, figures, an analysis report
The status strip tells you where you are Under the toolbar, a strip shows Plates · MS runs · Reference · Classified · FASTA. Anything not yet satisfied is a link — click it to run the step that satisfies it. These are project totals, not filtered-view counts.

Quick start

  1. Create a project. File ▸ New Project… A project is a single .db file plus an imports/ folder that holds copies of your data.
  2. Register a plate. Import ▸ Import Plate Metadata… Do this first — MS data cannot be imported until at least one plate exists. If you have a cellenONE isolation run, attach it here and its cells and images come in with the plate.
  3. Import your MS quantification. Import ▸ Parquet File… for DIA-NN output, or Import ▸ Excel Gene Matrix… for a gene/pg matrix. Assign each run's plate and biological condition before the Import button enables.
  4. Link cells to runs. Utils ▸ Reconcile Cells ↔ Runs… if you imported cellenONE data.
  5. Set quality filters. On the Explorer tab, set the minimum protein count and review the contaminant ratio.
  6. Import a reference profile. Import ▸ Omic Profile… — this defines the candidate cell types.
  7. Classify and explore. Colour by Cell Type, switch to PCA or UMAP, run GO enrichment.
  8. Export. Utils ▸ Export to PatternLab (PLP)… and Utils ▸ Export Analysis Report…

Projects

A project is self-contained: the SQLite database holds plates, runs, quantities, isolation metadata, images, classifications and settings, and imported source files are copied into the project's imports/ folder so the project keeps working if the originals move.

Opening, reloading, closing

  • File ▸ Open Project… — recent projects are also listed on the welcome screen.
  • File ▸ Reload Project Data (F5) — re-reads imports from disk. Use this after restoring a missing file, or if something looks stale.
  • File ▸ Close Project — clears the session; nothing is lost.
If files are missing If an imported file is absent from imports/ at open time, SCPBrowser tells you exactly which ones and marks the window title PARTIAL DATA. Every count, figure and export then reflects only the files that loaded. Restore the missing files and press F5 — do not re-import, which would duplicate runs.

Plates & cellenONE integration

A plate represents one physical sample carrier. Every MS run belongs to a plate, which is why a plate must exist before data can be imported.

Registering a plate

Import ▸ Import Plate Metadata… Give the plate a name and, optionally, run date, instrument, operator and a description. If you attach a cellenONE isolation run in the same dialog, these fields are auto-filled from the run and its cells and images are imported against the new plate.

Attaching an isolation run later

Import ▸ Import cellenONE Run into Existing Plate… for when the isolation data arrives after the plate was registered. Choose the target plate — the picker shows what each plate already holds — and select the .Run folder containing the *_isolated.xls file.

Safeguards Re-importing the same run is deduplicated and reported as such. If the run is already attached to a different plate, you are warned before anything is written, because that would create a second copy of the same cells. The import is irreversible, so the target plate is worth checking.

What is imported

For each dispensed well: drop number, target well, field position, X/Y position, diameter, elongation, circularity, transmitted and fluorescence intensity, isolation timestamp, and the cropped transmitted-light micrograph (plus fluorescence channels where present).

Image-based doublet QC

Open Utils ▸ Cell Plate Viewer… to inspect an isolation run: the plate layout with per-well micrographs, the isolation metadata for a selected well, a gating scatter, and the image-derived cell count.

Why the image is necessary

Standard proteomic quality metrics — peptide count, signal intensity, coefficient of variation — cannot identify wells that received more than one cell. A doublet carries roughly twice the protein and therefore scores better on those metrics than a singlet. Discriminating multiplets requires a signal orthogonal to the proteomic measurement, and the isolation micrograph provides one at no additional experimental cost. The rationale is set out by Loi et al. (preprint, 2025), whose scpImaging pipeline established the approach.

Instrument counts and morphology gates are not sufficient A well can contain two cells while the instrument's own object counter records one, and while the recorded morphology (diameter, elongation, circularity) sits comfortably inside the singlet gates used during isolation. Such an event is invisible to the isolation-time criteria and, for the reason above, invisible to the downstream proteomic filters as well. Only re-segmenting the micrograph resolves it.

Reviewing and excluding

Wells whose image-derived count exceeds one are flagged automatically. For each flagged well you can Keep, Discard, or annotate with a note. Discarded wells are excluded from downstream analysis, and the exclusion is recorded with the reason cellenONE QC: discarded, so an automated QC exclusion stays distinguishable from one made by hand later.

Because the link is stored in the project, every cell-type assignment remains traceable to the image of the cell it came from.

Importing MS data

DIA-NN parquet

Import ▸ Parquet File… Select the report, then assign every run a plate and a biological condition. The Import button stays disabled until the dialog has everything it needs, and it tells you what is missing.

Confidence filterIdentifications are filtered at 1% FDR using Q.Value and PG.Q.Value where those columns exist. An identification carrying no q-value is rejected rather than admitted.

Excel gene matrix

Import ▸ Excel Gene Matrix… for a gene- or protein-group matrix. Cell type is auto-detected from each sample's folder path. Gene-matrix projects have no peptide dimension, so peptide-specific columns are hidden rather than filled with a duplicate of the protein count.

Formats cannot be mixed Parquet and Excel intensities are not comparable, so a project holds one or the other. SCPBrowser refuses the second format and explains why.

Search database

Import ▸ Search Database (FASTA)… enables sequence coverage in the Protein Coverage tab. Optional; everything else works without it.

Reconciling cells ↔ runs

Utils ▸ Reconcile Cells ↔ Runs… links each isolated well to its mass-spectrometry raw file. Until this is done the isolation data and the proteomic data exist side by side but are not connected, so image-based exclusions cannot reach the analysis.

  1. Choose the isolation run.
  2. Suggest proposes matches using the selected strategy.
  3. Correct any row by hand — set a run to (none) to leave a cell unlinked.
  4. Apply links writes the result.
Apply replaces the run's links Applying clears the selected run's existing links and writes the current table in one transaction, so a failure part-way cannot leave the run half-linked. If you have curated links by hand, be aware that Apply replaces them with what is on screen.

Quality control

Protein-count filters

On the Explorer tab, Min. Proteins G. sets the minimum protein groups a cell must have to enter the analysis; Max. Proteins G. sets an upper bound (useful for spotting outliers). The minimum is also in Utils ▸ Settings and the two stay in step — changing it in either place re-filters the open session immediately.

Contaminants

On the Protein Matrix tab, mark protein groups as contaminants and press Apply Contaminants to compute a per-cell contaminant ratio, which becomes a colouring mode and an exclusion criterion.

  • Bundled cRAP… marks a conservative cRAP subset (keratins, proteases, serum and milk proteins). Every match is listed for confirmation first.
  • Load list… accepts a plain one-per-line accession list or a FASTA, so the official cRAP file can be used directly.
  • Multi-select rows, or filter with the search box and use Select All Visible.
Nothing is excluded until you apply Marking a protein only tags it. The contaminant ratio and any exclusion take effect when you press Apply Contaminants. Note that some bundled entries (albumin, transferrin, immunoglobulins) are genuine human proteins that are contaminants only in the sense of culture/serum carry-over — judge them for your experiment.

Excluding individual cells

Uncheck a run in the selected-points grid, or exclude from the Cell Plate Viewer. Clear Exclusions restores every manually excluded run in the project — it is not limited to the current selection, and it cannot be undone.

Reference profiles

Classification compares each cell against a reference profile per candidate class. Import ▸ Omic Profile (Transcriptomic / Proteomic)… accepts:

  • a transcriptomic matrix (TSV) plus metadata,
  • a .pref proteomic reference,
  • a parquet dataset you label yourself, from which a proteomic reference is built.
Importing a reference replaces the previous one The profiles are replaced wholesale, so any existing cell-type assignments were produced by a reference that no longer exists. SCPBrowser therefore discards those assignments and offers to reclassify immediately. Take the offer, or classify again before reading any figure.
Transcriptomic references: a caveat Transcript and protein abundances correlate only partially, so a transcriptomic reference encodes relationships that need not hold at the protein level, and a transcriptionally discriminative marker may be poorly measured in a single-cell proteome. Where a proteomic reference is available, prefer it; where it is not, read assignments together with the confidence and stability diagnostics rather than as categorical labels.

Cell-type classification

Each cell is scored against every candidate class and assigned to the highest-scoring one. Two scorers are available; the project remembers which it uses, and results from one are never displayed as the other's.

MethodHow it scoresUse when
QScore (default) Four rank-based channels — Spearman correlation, a signature-rank term, a Mann–Whitney AUROC, and a detection log-likelihood — combined by log-pooling (a product of experts). Generally. It is the better-validated scorer and treats absence as evidence.
Standard Four metrics — correlation, specificity-weighted similarity, marker enrichment, marker coverage — each softmaxed and averaged. Reproducing earlier analyses made with this method.

Scores and margins

Scores are normalised across the candidate classes so they sum to one. The assignment score is the winning value and the margin is the gap to the runner-up.

The score is a relative share, not a probability Because the scores are forced to sum to one, the classifier cannot answer "none of these": a cell whose true type is absent from the reference still receives a high score for whichever listed class it least disagrees with. Always read the score together with the margin — a top share of 0.35 with a 0.02 margin is a very different statement from 0.35 with a 0.20 margin.

Adding domain knowledge

In the Project Browser you can supply key markers per class, exclude classes that cannot occur in your sample, and set prior weights for expected population frequencies. These act as multiplicative adjustments on the scores — they bias the result without overriding the data. All are optional; by default the classifier runs unaided.

Confidence threshold

The Min Confidence slider on the Explorer relabels cells below the threshold as Undetermined rather than discarding them. The default is 10%.

Validating the classifier

Evaluate Classifier

Utils ▸ Evaluate Classifier… benchmarks classification against your biological conditions as ground truth. It runs repeated stratified k-fold cross-validation and leave-one-out, rebuilding the reference from each fold's training cells so no cell is ever scored against a reference it contributed to. It also reports a learning curve, per-channel contributions, and subset-resampling stability.

The dialog opens preselected to the classifier your project actually uses. Export produces a self-contained HTML report with figures plus a plain-text file of the numbers.

Nothing is saved to the project Every fold builds its reference in memory. Results leave only through the files you export.

Subset stability

Each cell is re-classified from random halves of its detected proteins. Agreement with the full-data call tells you whether an assignment rests on broad evidence or on a few proteins that happened to be measured. This is a different question from confidence: a cell can be assigned correctly with a large margin and still be sensitive to which proteins were captured.

Classification Confidence Map

Utils ▸ Classification Confidence Map… produces a per-cell × per-class figure with a margin plot, using the project's selected classifier and its key markers, exclusions and priors. The heatmap is a display of relative scores over the full reference, not a held-out estimate — held-out validation is overlaid separately, and cells that could not be evaluated are marked rather than assumed correct.

Dimensionality reduction

Switch the Explorer's view mode to PCA or UMAP. The settings popup controls the whole preprocessing pipeline; every parameter has a tooltip stating its default and effect.

Preprocessing order

select proteins → log₂ → per-cell normalisation → optional batch correction → optional z-score → clip.

SettingDefaultWhat it does
Per-cell normMedian-centre Removes per-cell differences in input amount, cell size and depth. Without it PC1 easily becomes a depth axis that looks like a cell population. None reproduces analyses made before this option existed.
Missing valuesProtein mean How unquantified proteins are filled in. Zero treats "not measured" as a measured zero, which with 40–70% missingness drags each protein's centre down and inflates its variance.

Read the plot header It states how many proteins the embedding actually used, the realised missingness, whether the HVP filter was bypassed because too few cells were available to score variability, and — for batch correction — if the correction was skipped or fell back to plate-only.

K-means

Colour by K-means to cluster on the currently displayed axes. The basis (for example UMAP axes, k=5) is shown next to the control and stored with the assignments, so a saved clustering always records what it was computed on. Clusters are data-driven groupings, not cell-type calls.

GO enrichment

Configure an ontology and species annotations once via Utils ▸ GO Database…. GO is optional — everything else works without it, and only GO-dependent views are disabled until it is present.

Enrichment uses a hypergeometric test with Benjamini–Hochberg FDR control. Redundant terms are reduced by semantic similarity (a REVIGO port) and rendered as a weighted Voronoi treemap in the BioTessera tab, where tile area encodes the chosen metric and colour encodes fold change.

Interpreting the treemap Area encodes the weight only insofar as the layout solver converged; check the reported area error before treating relative tile sizes as quantitative. Terms that cannot be rendered are reported rather than silently omitted.

Export & reporting

  • Utils ▸ Export to PatternLab (PLP)… — annotated dataset for differential analysis, carrying cell-type and condition labels.
  • Utils ▸ Export Analysis Report… — the settings behind the current figures: filters, normalisation, HVP state, batch correction, seeds, excluded runs.
  • Figures — the evaluation report and confidence map export as self-contained HTML plus standalone SVG, on a white background for manuscript pages.
  • Protein matrix — CSV export of the quantification table.

Reproducibility

To describe an analysis in a manuscript, or repeat it later:

  1. Export the analysis report — it records the parameters that produced the current figures.
  2. Note the classifier method (QScore or Standard) and whether key markers, priors or exclusions were used.
  3. Note the reference profile's origin — proteomic or transcriptomic, and which dataset.
  4. Keep the UMAP seed if the embedding is shown; with the same seed and settings it reproduces exactly.
  5. Report the QC thresholds: minimum protein count, contaminant handling, and any excluded cells.

The source code is available at github.com/pcarvalho75/SCPBrowser.

Troubleshooting

The Import button stays disabled

The dialog states the reason beneath the button: no plate registered, no file chosen, or runs still missing a plate or biological condition. Register a plate first if you have none.

Colour by Cell Type is greyed out

No reference profile is loaded. Use Import ▸ Omic Profile….

The window title says PARTIAL DATA

Imported files are missing from imports/. Restore them and press F5. Do not re-import — that creates duplicate runs.

Cell types disappeared after importing a reference

Expected: the previous assignments came from the reference you replaced and were discarded. Reclassify.

Cell Plate Viewer is empty

The project has no cellenONE data. Attach a run via Import ▸ Import cellenONE Run into Existing Plate….

Image exclusions are not affecting the analysis

Cells must be linked to their MS runs first — Utils ▸ Reconcile Cells ↔ Runs….

Numbers changed after an update

Check the analysis report and the plot header: the protein count used, the normalisation and missing-value modes, and the HVP state are all stated there. The pre-existing behaviours remain selectable (None, Zero, HVP off) if you need to reproduce an earlier figure.
