Transmutation Learning

Breaking the Reference Database Barrier in Single-Cell Proteomics

A pragmatic framework for bootstrapping cell-type classification in single-cell proteomics by leveraging transcriptomic references — bridging the gap from the napkin sketch to the real thing.

↓ Explore the Workflow Read the Concept
The Problem

A Reference Database Barrier

Single-cell transcriptomics has built a vast reference infrastructure over the past decade. Single-cell proteomics has no comparable ecosystem — and the gap is unlikely to close rapidly.

Transcriptomics: Rich Infrastructure

Pre-trained classifiers like CellTypist and SingleR, standardized cell ontologies, and atlas-scale references built by thousands of scientists over a decade. Billions of dollars and millions of researcher-hours invested.

🔬

Proteomics: Fragmented Landscape

No standardized cell-type ontologies, no pre-trained classifiers for automated annotation, and limited community-scale references. Researchers often rely on manual annotation or methodological improvisation.

⏱

The Throughput Gap

Sequencing's inherent throughput advantages over mass spectrometry, combined with transcriptomics' decade head start, mean proteomics cannot simply replicate this infrastructure within a practical timeframe.

🌉

The Bridge We Need

Instead of waiting to build proteomic references from scratch, can we leverage the existing transcriptomic knowledge to bootstrap proteomic classification? That's the question Transmutation Learning aims to answer.

The Concept

From the Napkin Sketch to the Real Thing

Imagine someone who has never seen a car. You sketch one on a napkin — four wheels, a body, windows — and send them outside. They'll succeed most of the time, perhaps confusing a van for a sedan, but the imperfect sketch is sufficient to bootstrap real-world learning.

📝

The Napkin Sketch

Transcriptomic references provide an approximate representation of cell identity — not through the same molecular features, but through a correlated proxy. mRNA profiles sketch what the protein landscape should look like.

→
🚗

The Real Thing

High-confidence assignments become reliable proteomic training examples, enabling construction of proteomics-native classifiers that no longer depend on transcriptomic proxies. The sketch bootstraps real-world knowledge.

Where Does This Fit?

Transmutation Learning is conceptually rooted in cross-domain pseudo-labeling, but names a specific cross-modal workflow that existing paradigms don't capture. The cross-modal gap between mRNA and protein is not merely a domain shift — it's a change in molecular layer.

The Workflow

Two-Tier Bootstrap Architecture

Transmutation Learning operates in two tiers: first, it leverages transcriptomic knowledge to generate provisional labels; then, it builds proteomics-native classifiers from the confidently assigned cells.

01

🧬 Cross-Modal Classification

Classify proteomic data against transcriptomic references using shared marker-based enrichment scores mapped via gene-to-protein identifiers. The system leverages tools like SingleR to generate provisional cell-type labels, accepting that mRNA–protein correlation is imperfect.

TIER 1 — TRANSCRIPTOMIC PROXY
02

🔍 Confidence Filtering

Apply configurable thresholds (delta scores, label pruning, expected distribution priors) to retain only high-confidence assignments. This is the critical step — the subset passing stringent filtering serves as a reliable anchor for downstream training. Cells that fail are excluded, not forced into incorrect categories.

QUALITY GATE
03

📊 Proteomics-Native Feature Selection

Using the confidently classified cells as a proteomics-native training set, perform feature selection directly on proteomic measurements. Kruskal-Wallis testing with Benjamini-Hochberg FDR correction identifies discriminative protein markers. Redundancy filtering via Spearman correlation removes correlated markers.

TIER 2 — PROTEOMICS-NATIVE
04

🎯 Iterative Distillation & Export

Iteratively refine labels through kNN-based distillation using dual-mode similarity (intensity-based cosine + detection pattern Jaccard) with optional PPI-informed biological priors. Cross-validation monitors for overfitting. The final classifier is exported as a proteomics reference for downstream annotation.

REFINEMENT & DEPLOYMENT
Software

Current Implementation

A standalone desktop application built in C# / WPF, currently under active development. The tool implements the full Transmutation Learning workflow.

🔀

Dual-Mode Similarity

Combines cosine similarity on shared protein intensities with Jaccard similarity on detection patterns — leveraging the "shared silence" of missing values in SCP data.

🧲

Biological Gravity

Optional PPI-informed similarity using STRING database. Cells expressing interacting proteins are pulled closer together, respecting the physical interactome.

🔄

Iterative Distillation

Self-adjusting iterative loop: auto-selects markers, refines labels via kNN voting, checks convergence, and uses cross-validation as an early stopping criterion.

📈

Adaptive Marker Selection

Kruskal-Wallis + Benjamini-Hochberg FDR correction with greedy forward selection to remove redundant markers. Auto-relaxes thresholds when too few markers pass.

🛡️

Confidence Gating

Otsu's method for automatic threshold selection on delta scores, valid label set filtering, and expected distribution priors with configurable sensitivity.

📦

Reference Export

Exports trained proteomics-native classifiers as .pref files containing expression matrices, detection matrices, and marker statistics for downstream annotation.

Transparency

Known Limitations & Open Questions

Transmutation Learning does not claim all assignments are correct. We believe in transparent science and want to be upfront about what this approach can and cannot do.

⚠️ mRNA–Protein Discordance

Post-transcriptional regulation, protein stability differences, and degradation dynamics mean mRNA and protein levels show imperfect correlation. Some cell types will transfer poorly from transcriptomic references.

⚠️ Detection Bias in SCP

Mass spectrometry detection is abundance-biased. Low-abundance marker proteins critical for distinguishing rare cell types may be systematically missed, reducing classifier performance for those populations.

⚠️ Cell-Type Abundance Bias

Rare cell types poorly represented in the transcriptomic reference may fail confidence filtering entirely and become invisible to the proteomics classifier. The approach inherently favors well-characterized, abundant cell types.

⚠️ Transcriptomic Bias Propagation

If the transcriptomic reference contains systematic biases or misannotations, these errors can propagate into the proteomics classifier. The confidence filtering mitigates but cannot eliminate this risk.

⚠️ Centroid-Based Validation Limits

The current cross-validation uses centroid classifiers that assume spherical clusters. Developmental trajectories or complex non-spherical distributions may fail validation even when the underlying classification is biologically meaningful.

⚠️ No Independent Benchmarking Yet

The tool has not been validated against independent ground truth such as FACS-sorted datasets. Until such benchmarking is completed, all results should be treated as preliminary and interpreted with caution.

Community Discussion

Questions We Want to Debate

We invite the proteomics community to engage with these open questions.

Is approximate knowledge from a related modality preferable to no reference at all? Where is the line between useful bootstrapping and dangerous bias propagation?

What confidence thresholds best balance coverage against accuracy? Should these be tissue-specific, or can universal guidelines be established?

Can Transmutation Learning accelerate the construction of proteomic reference atlases? What collaborative infrastructure would the community need?
